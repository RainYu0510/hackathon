# hackathon — 偽 2D 平台遊戲原型

玩法邏輯全部在 2D 平面;3D 場景只用來當背景,透過 SubViewport render 成
貼圖放在 2D 層後面。兩層完全解耦,各自留一個後製濾鏡插槽。

兩個玩家共用**一個鏡頭**,規則是**落後者優先**:鏡頭只由落後的那個人驅動,
永遠不會把他推出畫面。領先者跑再遠鏡頭都不動,直到落後者跟上。

**這個遊戲必須能在瀏覽器裡玩。最終驗收權威是 Chrome,不是桌面執行。**

Godot **4.7.2**,renderer 鎖 **Compatibility**(`gl_compatibility`)——
不是效能取捨,是硬需求:WebGL2 只支援這一個。

## 操作

| | 左 | 右 | 跳 |
|---|---|---|---|
| **P1** | A | D | W |
| **P2** | J | L | I |
| **P2**(數字鍵盤) | 4 | 6 | 8 |

`R` = 重置。**掉出界時兩個人一起回出生點**,不是只有掉下去的那個 —— 一個人
失誤兩個人一起回去,是刻意的合作壓力。

**P2 不用方向鍵。** 這台鍵盤實測 `W + ↑ + →` 三顆同時按時 `→` 會被鍵盤矩陣
封鎖掉(ghosting/blocking),而這關是往右走的,等於「P1 跳的時候 P2 不能
往右跳」。IJKL 與數字鍵盤 4/6/8 實測四鍵全過。完整實測表在 dev-log。

數字鍵盤那組是額外綁的,**還沒實測 NumLock 關閉時是否仍然有效** —— 主力
是 IJKL,它不依賴 NumLock,也不要求鍵盤有數字區。

兩個玩家**不會互相碰撞**,可以直接穿過對方。

## 跑起來

```bash
# 桌面(開發迴圈)
godot --path .

# Flatpak
flatpak run org.godotengine.Godot --path .
```

第一次在新機器上要先建 `.godot/` 快取,否則 `class_name` 找不到:

```bash
godot --headless --path . --import
```

## 畫質

只有一個旋鈕 —— `scripts/main.gd` 的 `render_divisor`:

| divisor | 渲染解析度 |
|---|---|
| 1 | 1920x1080 |
| 2 | 960x540 |
| 3 | 640x360 |
| **4**(預設) | **480x270** |
| 6 | 320x180 |

**改這個值不用動關卡資料或物理常數。** 世界座標空間永遠是 1920x1080,
相機 zoom 會同步補償,所以可視世界不變、`half_w` 恆為 960。

## 關卡

`data/level_01.json`。座標定義:**x = 平台左緣,y = 平台上緣(踩踏面)**,
單位是邏輯單位。`spawns` 的 x/y 是玩家碰撞箱中心。

載入時會斷言地面列的缺口不超過 `MAX_GAP = 350`,並印出所有相鄰平台的
Δx / Δy 落差表給人眼掃。斷言 fail 會直接報錯,不讓過不去的關卡默默上線。
