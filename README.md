# hackathon — 偽 2D 平台遊戲原型

玩法邏輯全部在 2D 平面;3D 場景只用來當背景,透過 SubViewport render 成
貼圖放在 2D 層後面。兩層完全解耦,各自留一個後製濾鏡插槽。

兩個玩家共用**一個鏡頭**,規則是**落後者優先**:鏡頭只由落後的那個人驅動,
永遠不會把他推出畫面。領先者跑再遠鏡頭都不動,直到落後者跟上。

**這個遊戲必須能在瀏覽器裡玩。最終驗收權威是 Chrome,不是桌面執行。**

Godot **4.7.2**,renderer 鎖 **Compatibility**(`gl_compatibility`)——
不是效能取捨,是硬需求:WebGL2 只支援這一個。

## 操作

| | 左 | 右 | 跳 | 切換空間 |
|---|---|---|---|---|
| **P1** | A | D | W | 左 Shift |
| **P2** | J | L | I | 右 Shift |
| **P2**(數字鍵盤) | 4 | 6 | 8 | — |

**切換空間鍵目前是暫定的**,等 5 鍵 rollover 實測表回來才定案 —— 見下面
〈同時按鍵的上限〉。而且**要先撿到護目鏡才有作用**,而且只有撿到的那個人
按得動,另一個人按自己的切換鍵不會有反應。

`R` = 重置(除錯用,連拾取物一起清,真的回到開場)。

**掉出界時兩個人一起回出生點**,不是只有掉下去的那個 —— 一個人失誤兩個人
一起回去,是刻意的合作壓力。但**拾取物會保留**:封閉房間是一次性的教學,
跑酷失手不該罰你重看一次。

### 同時按鍵的上限

**P2 不用方向鍵。** 這台鍵盤實測 `W + ↑ + →` 三顆同時按時 `→` 會被鍵盤矩陣
封鎖掉(ghosting/blocking),而這關是往右走的,等於「P1 跳的時候 P2 不能
往右跳」。IJKL 與數字鍵盤 4/6/8 實測四鍵全過。完整實測表在 dev-log。

**加上切換空間之後最壞情況是同時 5 鍵**(兩人各按方向 + 跳,再加切換鍵)——
「跳到一半切空間」正是這個機制的核心動作,不是邊緣情況。舊那張四鍵的表
不能外推,所以切換鍵在 5 鍵實測表回來之前只是暫定值。

**Ctrl 不能當遊戲鍵**:P1 的跳躍是 `W`,`Ctrl+W` 在瀏覽器是關閉分頁,而且
`preventDefault()` 攔不住(瀏覽器保留鍵,跟方向鍵捲頁不是同一個層級)。
空白鍵排在最後,因為它會捲頁。

數字鍵盤那組是額外綁的,**還沒實測 NumLock 關閉時是否仍然有效** —— 主力
是 IJKL,它不依賴 NumLock,也不要求鍵盤有數字區。

兩個玩家**不會互相碰撞**,可以直接穿過對方。

## 跑起來

```bash
# 桌面(開發迴圈)
godot --path .

# Flatpak
flatpak run org.godotengine.Godot --path .
```

第一次在新機器上要先建 `.godot/` 快取,否則 `class_name` 找不到:

```bash
godot --headless --path . --import
```

## 畫質

只有一個旋鈕 —— `scripts/main.gd` 的 `render_divisor`:

| divisor | 渲染解析度 |
|---|---|
| 1 | 1920x1080 |
| **2**(預設) | **960x540** |
| 4 | 480x270 |
| 8 | 240x135 |

**改這個值不用動關卡資料或物理常數。** 世界座標空間永遠是 1920x1080,
相機 zoom 會同步補償,所以可視世界不變、`half_w` 恆為 960。

可用值只有 `{1, 2, 4, 8}`:必須同時整除 88(角色高)與 1920/1080。
3 和 6 雖然整除畫面,但 88/3、88/6 不是整數,貼圖會對不齊像素格。
**但它跟玩家貼圖是綁在一起的**,改它就要一起改 `make_spritesheet.py` 的
`--height` 與 `player.tscn` 的 sprite scale —— 三者不一致時 `Player._ready()`
會 `push_error` 擋下來,不會靜默畫錯。

## 關卡

`data/level_01.json`。座標定義:**平台的 x = 左緣,y = 上緣(踩踏面)**;
`spawns` 與 `pickups` 的 x/y 是**中心**。單位是邏輯單位。

### 兩個空間

每塊平台有一個 `space` 欄位:`normal` / `alt` / `both`(缺欄位時當 `both`)。
非作用空間的平台仍然畫得出來,只是半透明而且沒有碰撞 —— **那個幽靈預覽是
機制的一部分,不是裝飾**,沒有它就是閉著眼睛跳。

切換空間改的是**兩個玩家的 `collision_mask`**,平台的 `collision_layer` 設定
一次之後不變。這樣兩個空間永遠都查得到,切換前才能預檢「會不會卡進牆裡」——
會卡就擋下切換,不是切完再讓物理把人推出來。

第一關的結構:封閉房間(右牆只存在於正常空間,撿到護目鏡切過去就走得出來)
→ 中段跑酷(柱子與細台交錯,同空間相鄰間隔 620,遠大於跳得過去的 350,
所以任何一個空間單獨都走不通)→ 破碎的異空間房間,盡頭是鑰匙。

### 載入時的檢查

- **相鄰平台落差表**:Δx / Δy 印出來給人眼掃,含 `space` 欄
- **跨空間 x 投影聯集斷言**:把所有平台(不分空間)在 x 軸上的投影取聯集,
  不得存在一段長度 > `MAX_GAP = 350` 的區間是兩個空間都沒有落腳面的

第二條才是硬斷言,fail 會直接報錯,不讓過不去的關卡默默上線。
它刻意**不**假裝是完整的可達性演算法:垂直方向只印表,不斷言。
